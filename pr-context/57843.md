# PR #57843 — fix(delivery): disambiguate hook cancellations from delivery failures

## Stated purpose

Make `deliverOutboundPayloads`'s return value carry enough metadata that
callers can distinguish three previously indistinguishable outcomes:

1. All payloads cancelled by `message_sending` hook (intentional policy)
2. Genuine zero-result delivery failure (silent, fall through to retry/log)
3. Partial send: some payloads delivered then a later payload threw
   (must NOT replay the sent prefix on retry)

## In scope

- `DeliveryOutcome` type — `OutboundDeliveryResult[]` augmented with
  non-enumerable `cancelledCount` and `allCancelledByHook` metadata.
  Back-compat: existing array-shape consumers unchanged.
- `DeliveryError` class with `sentBeforeError: OutboundDeliveryResult[]`,
  thrown when a non-bestEffort send fails after at least one payload landed.

- Tests for all of the above paths (the bulk of the diff: ~187 lines in
  `deliver.test.ts`, plus ack-on-DeliveryError tests in restart-sentinel
  and delivery-queue-recovery test files)

## Implementation notes / gotchas

- `DeliveryOutcome` is implemented as `Array & { ... }` with metadata
  attached via `Object.defineProperty(..., enumerable: false)`. Necessary
  because `toEqual([...])` and `toMatchObject([...])` would otherwise see
  the metadata as extra own properties and fail.
- The `isDeliveryError(err)` guard uses a name + shape check (not
  `instanceof`) on purpose: the cron path imports `DeliveryError` as a
  type-only to keep the heavy outbound module off cold-startup, and the
  restart-sentinel test mocks the deliver module without re-exporting the
  class. `instanceof undefined` would throw TypeError in mocked tests.

## Lessons captured

- Round-2 codex review caught that I had broken plugin-SDK back-compat by
  switching the return type from array to object. Fix: array-augmented
  type. **Pattern:** check public re-exports (`src/plugin-sdk/*`) before
  changing a function's return shape.
- Round-3 codex review caught that the WAL queue still left entries
  pending after a partial-send `DeliveryError`, so recovery would replay.
  Fix: ack-on-DeliveryError in 3 places. **Pattern:** when the function
  signals "terminal failure with side effects already committed", the
  durable queue MUST ack, not fail-with-retry.
- Silent rebase regressions on unrelated files (`refresh.ts`,
  `daemon-install-helpers.ts`, etc.) — git's 3-way merge sometimes picks
  the older side when both sides changed and our PR didn't touch the file.
  **Pattern:** always check `git diff upstream/main..HEAD --stat` for
  unexpected files after rebase; restore them with
  `git checkout upstream/main -- <files>` and amend.
