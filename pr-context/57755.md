## Stated purpose

Make `openclaw agent --json --deliver`'s output carry the `deliveryStatus`
field that #53961 already tracks internally, so automation around the CLI
can detect silent delivery failures, hook cancellations, and partial sends
without grepping stderr.

## In scope (delta over #53961)

- `deliveryStatus` field in the `--json` envelope at every exit point
  (succeeded, partial, error, no-payload, no-deliver).
- `succeeded: boolean | "partial"` 3-state — third value indicates
  bestEffort sent some chunks but recorded an `onError` for at least one
  later chunk.
- `emitJsonEnvelope` helper that consolidates the "emit envelope, with or
  without deliveryStatus" call pattern.
- Deferred emission: when `--json && --deliver`, the envelope is emitted
  AFTER delivery completes (so `deliveryStatus` is available), not before.
- Emit-on-strict-throw: in non-bestEffort mode when delivery throws, emit
  the structured envelope BEFORE re-throwing so `--json` callers always get
  parseable stdout on transport failure.

## NOT in scope

- Internal status tracking (variables, try/catch, return value field) —
  that's #53961's job. This PR currently CARRIES that code in its diff
  because #53961 hasn't merged yet, but on merge order #57755-after-#53961,
  the diff naturally narrows to just the JSON-side additions.
- Hook-cancellation false-positive suppression — same as #53961's
  follow-up scope.

## Vincentkoc's clownfish review fixes (commit `a8fc4407e9`)

Maintainer @vincentkoc force-pushed a "narrow repair" commit on
2026-04-28 that introduces `recordDeliveryResult(result)` /
`recordDeliveryResults(...)` helpers in `src/infra/outbound/deliver.ts`,
plus a `params.onDeliveryResult` callback. Purpose: centralize the
"push to results array + notify caller" pattern so callers can subscribe
to per-payload completion without scraping the final array.

**Conflict gotcha:** vincentkoc's helper does NOT call
`hasDeliveryResultIdentity`. Upstream's pre-existing code at the
sendPayload site DOES skip results that fail that check. When resolving
conflicts that touch this site, KEEP the identity-check guard before
calling `recordDeliveryResult(delivery)` — that's the union of
vincentkoc's intent (centralize recording) and upstream's behavior
(skip no-op sends).

## Implementation notes / gotchas

- The `succeeded: boolean | "partial"` field is unique to this PR. Tests
  that assert `succeeded: true` after a "successful but partial" run
  (i.e. bestEffort with `onError` fired but `results.length > 0`) need
  to be updated to assert `"partial"` instead.
